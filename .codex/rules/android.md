# Android Rule

- MVVM을 기본 구조로 사용합니다. Composable은 UI를 그리고 이벤트를 전달하며, `ViewModel`은 화면 상태와 작업을 관리하고, Repository는 데이터 접근을 담당합니다.
- Composable에서 Retrofit 호출, `SharedPreferences` 접근, 권한 판단, 장기 폴링 작업을 직접 처리하지 않습니다.
- 화면 상태는 불변 `UiState`로 노출하고 비동기 작업은 `viewModelScope`에서 실행합니다.
- 네비게이션 route는 한 곳에서 정의하며 권한이 필요한 목적지에는 서버 기준 권한 검증을 적용합니다.
- 객체지향 설계와 SOLID 원칙을 따르되, 원칙을 이유로 불필요한 계층이나 추상화를 추가하지 않습니다.
- 인터페이스는 외부 서비스 경계, 테스트 대역, 다중 구현이 필요한 경우에만 만듭니다.
- 사용자 입력은 경계에서 검증하고, 토큰, 비밀번호, Authorization 헤더, 개인정보를 로그로 남기지 않습니다.
- 비즈니스 규칙, 상태 분기, 데이터 변환에는 단위 테스트를 추가합니다. 단순 DTO, 단순 위임, 단순 getter에는 별도 테스트를 만들지 않습니다.
